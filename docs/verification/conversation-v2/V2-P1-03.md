# V2-P1-03 — Admin v2 catalog publication and tenant isolation

Date: 2026-10-30
Issue: GitHub #89
Branch: `feat/conversation-engine-v2`

## Result

**COMPLETE for the v2 Admin boundary scope.** A separate v2 catalog store and
Admin API support preview, draft creation, tenant-scoped listing, explicit
publication and XLSX/JSON export. Existing v1 Admin routes and storage remain
unchanged for rollback.

Endpoints:

- `POST /api/v2/admin/intent-catalog/preview`
- `POST /api/v2/admin/intent-catalog/versions`
- `GET /api/v2/admin/intent-catalog/versions`
- `POST /api/v2/admin/intent-catalog/versions/:id/publish`
- `GET /api/v2/admin/intent-catalog/published/export` (XLSX)
- `GET /api/v2/admin/intent-catalog/published/export.json` (canonical JSON)

Publication requires strict v2 validation, the selected tenant scope, the
canonical catalog version reference and an authorized tenant/platform admin.
The v2 table is separate from `intent_catalog_versions`, so a v2 publication
cannot accidentally enter the legacy v1 chat resolver. The forward-only
migration is `infra/postgres/055-catalog-v2-versions.sql`.

The ingestion worker selects the dedicated v2 parser only when the workbook
contains `CatalogManifest`; legacy workbooks continue through the v1 parser and
are never silently coerced to v2.
