# V2-P2-03 — Discovery continuity and fact correction

Date: 2026-10-30  
Issue: GitHub #94  
Branch: `feat/conversation-engine-v2`

## Result

**IMPLEMENTED and verified.** Existing catalog-driven discovery, journey
continuity and provenance correction remain the authority. This change fixes a
specific stale-action defect: when a validated catalog slot changes through an
explicit correction, pending action proposals for the current session and
active opportunity are invalidated and audited before any new proposal is
considered.

## Behavior preserved

- Knowledge-only turns remain outside CRM lead capture and do not create a new
  opportunity.
- Active journey requirements survive knowledge interruptions and status/help
  turns through the existing `reduceIntentJourney` and session CAS path.
- Slot corrections update the value and visitor provenance with `corrected:
  true`; the current opportunity and pinned catalog remain unchanged.
- Only `awaiting_confirmation` and `awaiting_customer` actions in the active
  session/opportunity are invalidated. Completed, processing, provider-verified
  and unrelated-opportunity records are not rewritten.
- Consent is not inferred from a correction, and a new opportunity still
  receives a new journey identity rather than inheriting prior state.

## Defect and correction

The failed correction path already stored the corrected visa count, but its
slot-key detector did not recognize the `visa_count` catalog slot in an
explicit sentence such as “Actually, make that 5 visas.” As a result, a
pending proposal could remain eligible. The correction gate now requires both
a changed validated slot and explicit correction language, then marks only the
matching pending action `failed` and records a redacted audit event containing
the action ID, opportunity digest and corrected slot keys.
