# V2-P5-03 — Signed callbacks, evidence tiers and reconciliation status

Date: 2026-10-30
Issue: GitHub #110
Branch: `feat/conversation-engine-v2`

## Result

Added v2-only provider callback correlation checks in the existing Node
workflow completion and signed n8n callback paths. When an action is bound to
a v2 catalog version, the callback must match the server-owned session,
opportunity, pinned catalog version, action key and action revision in addition
to the existing tenant, execution, event, correlation and attempt checks.
Legacy callback compatibility remains unchanged for v1 actions. Signed nonce
replay protection and authenticated callback handling remain in place.

Added an evidence projection used by `get_action_status`:

- `transport_received` — no durable dispatch evidence yet.
- `dispatched` — transport/n8n acceptance or processing evidence only.
- `provider_record_verified` — explicit provider verification evidence.
- `mock_verified` — explicit deterministic mock evidence.
- `reconciliation_required` — ambiguous, stale or failed correlation/state.

Only the two explicit verified tiers are stage-completion eligible. An opaque
external reference, HTTP success, n8n execution or PDF does not upgrade the
evidence tier.
