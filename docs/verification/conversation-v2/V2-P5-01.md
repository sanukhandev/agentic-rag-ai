# V2-P5-01 — Catalog-authorized action proposal and confirmation gate

Date: 2026-10-30
Issue: GitHub #108
Branch: `feat/conversation-engine-v2`

## Result

Implemented a Node-owned v2 action gate in
`services/api/src/v2-action-gate.ts`. Model proposals are strict, untrusted
keys. The gate requires a published enabled ToolBinding and enabled workflow
binding, the pinned goal and current stage, a confirmed business goal, all
catalog-required verified facts, purpose-specific consent, and the expected
action revision. Model-supplied identity, opportunity, revision, URLs and
idempotency values are not accepted.

Eligible proposals reuse the existing `ActionGateway` to create an
`awaiting_confirmation` `ActionRequest`. The existing gateway remains the
only approval/outbox path; no provider call is made while a proposal is
pending. Confirmation requires the exact pending action ID and trusted
tenant/session/opportunity/catalog/action identity, plus explicit customer
confirmation and purpose consent. Existing ActionGateway idempotency prevents
duplicate action identities.

## Focused evidence

- v2 action-gate tests: **5 passed, 0 failed**.
- Covered: valid pending proposal, malformed/unknown or inactive binding,
  disabled workflow, goal/stage mismatch, missing requirements, missing goal
  confirmation, missing purpose consent, stale action revision, argument
  scope, wrong opportunity, wrong catalog revision, generic confirmation after
  another pending question, duplicate action identity, and explicit approval.
- API typecheck: **passed**.
- No real n8n, Salesforce, payment, document, invoice or contract operation
  was executed.
- No seven-stage E2E, 25-turn, or 200-message benchmark was run. Final
  acceptance remains held by issue #124.

## Boundary

This issue establishes proposal and confirmation authorization only. The
existing transactional outbox, Redis/n8n dispatch and provider callback
verification remain the subsequent P5/P6 implementation boundaries. A model
proposal is never interpreted as customer authorization or provider evidence.
