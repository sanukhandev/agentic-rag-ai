# V2-P7-02 — Cross-tenant, fault and budget validation

Date: 2026-10-30  
Issue: #121  
Branch: `feat/conversation-engine-v2`

## Result

Verified the existing v2 security and resilience boundaries with synthetic,
non-side-effectful tests. No runtime behavior required a new implementation:
the protections delivered by P2–P5 and the provider contracts already cover
the issue scope.

## Coverage

The focused Node suite verifies:

- active-source and tenant filtering, including revoked-source suppression;
- signed scope, session, catalog/persona pin, state revision and opportunity
  checks at the private tool gateway;
- rejection of unknown tools, model-supplied tenant/session identity and stale
  state;
- persona spoofing, wrong language, metadata leakage, prompt injection and
  unsupported provider-completion claims;
- OTP, payment credential and provider-secret redaction at the privacy
  boundary;
- duplicate action identity suppression, concurrent message claiming, stale
  revisions, forged/wrong-tenant callbacks and reconciliation-required states;
- Redis outbox append/replay/deduplication behavior around a relay crash; and
- explicit provider/mock evidence requirements before stage completion.

The Python model-gateway suite verifies:

- strict v2 envelope/tool/result schemas and server-derived identity;
- unknown-tool denial and duplicate function-call replay without duplicate
  gateway execution;
- invalid model arguments and bounded tool/model rounds;
- model 429 handling without an outer retry, retry-after behavior, provider
  timeout deadlines, circuit opening and bounded SDK retries; and
- structured output validation and redacted observability.

## Synthetic budget limits

The v2 contract bounds one turn to at most 8 model requests, 12 tool calls and
6 tool rounds. The current gateway also caps model output at 1,700 tokens,
limits concurrent provider calls to the configured bounded semaphore (default
2, maximum 4), and applies the configured request-per-minute limiter and
shared deadline. Test envelopes use smaller limits (3 model requests, 4 tool
calls and 2 rounds) and assert the typed fallback when the budget is exhausted.
The focused run does not claim a live deployment quota measurement or provider
token-usage reading; no provider call or customer side effect is fabricated.
