# V2-P7-03 — Manual seven-stage acceptance preflight

Date: 2026-10-30  
Issue: #122  
Branch: `feat/conversation-engine-v2`

## Result

Added a manual-only final acceptance preflight at
`tools/qa/ancfz-final-acceptance.mjs`. It defines the exact seven ordered
ANCFZ stages, one synthetic customer/session/opportunity boundary, continuity
checks, evidence requirements and the separate legal-registration status.

The preflight is deliberately not the final acceptance run. It performs no
HTTP, database, n8n, Salesforce, payment or signing-provider calls. The
existing `qa:ancfz-single-journey` runner remains available for focused work;
the complete seven-stage run is still reserved for the operator-triggered
manual gate in issue #124.

## Safety contract

- `--dry-run` is the only mode used by automated validation and prints a
  redacted plan only.
- `--execute` requires
  `ANCFZ_FINAL_ACCEPTANCE_CONFIRM=RUN_ANCFZ_FINAL_ACCEPTANCE` and is rejected
  when `CI=true` or `CODEX_AUTO_RUN=true`.
- Provider mode is restricted to `mock` or explicitly opted-in `sandbox`;
  real providers are rejected. Sandbox mode additionally requires
  `ANCFZ_ALLOW_SANDBOX=true`.
- The plan never exposes synthetic contact values, provider IDs, payment URLs,
  signing URLs or legal-registration claims.
- Real payments, legally binding signatures and legal registration remain
  disabled/separate evidence requirements.

## Commands

Safe preflight:

```powershell
npm run qa:ancfz-final-acceptance -- --dry-run --provider-mode=mock
```

An operator must separately authorize any future execution with the documented
manual confirmation environment and approved provider configuration. This task
does not execute that path.
