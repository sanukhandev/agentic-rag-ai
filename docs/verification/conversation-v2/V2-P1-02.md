## Result

**COMPLETE for the v2 runtime policy module scope.**
`services/api/src/catalog-v2-runtime.ts` adds the explicit trusted-published
catalog boundary, stage eligibility evaluator and score/readiness evaluator.
The existing v1 resolver in `intent-catalog.ts` is unchanged for rollback and
historical behavior.

The v2 evaluator:

- Requires `published`, trusted tenant scope and the canonical catalog version
  reference before accepting a catalog.
- Rejects duplicate keys, dependency cycles, later-stage requirement leakage,
  unsafe terminal evidence classes and enabled workflows unreachable from an
  enabled tool.
- Reports evidence score, configured threshold, ambiguity, confidence band,
  verified requirement coverage, missing requirements and action readiness as
  separate values.
- Uses catalog signal weights only; it never treats a model confidence value as
  authorization or as a calibrated probability.
- Does not know ANCFZ stage names in engine logic; the stages are fixture data.
