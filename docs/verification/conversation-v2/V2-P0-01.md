## Scope and safety

This is a baseline record for GitHub issue #82. No PostgreSQL migration was
changed or executed, no customer record was modified, no Salesforce/payment/
contract write was performed, and the full seven-stage E2E was not run. The
pre-existing untracked `artifacts/ancfz-single-journey/` directory was left
untouched.

The current branch contains the approved v2 planning documents and the initial
private Python model-gateway scaffold. It does not yet contain the v2
ConversationCoordinator, User Intent Document ledger, Python↔Node tool loop,
persona composer, response guard, or provider-verified seven-stage runtime.

## Existing capability map

- Node/Express owns tenant/session authorization, masking/token-vault use,
  catalog lookup, RAG orchestration, response shaping, consent and action
  policy.
- PostgreSQL/pgvector is the durable knowledge and business-state store;
  Redis is event/cache transport, not business truth.
- The existing action path persists idempotent `ActionRequest`/outbox state and
  routes authorized execution through the event relay, Redis Streams, worker
  and n8n callback/reconciliation path.
- The model gateway is a private FastAPI scaffold with `plan` and `normalize`
  operations, a service-key boundary and Azure OpenAI Responses API-key
  configuration. It has no database, n8n, Salesforce or CRM credentials.
- The existing public chat response remains the compatibility contract. The
  current `app.ts` orchestration is still the active lead-first path and is not
  silently replaced by the scaffold.

## Rollback and no-data-loss contract

1. Keep the existing `CHAT_MODEL_PROVIDER` path and public Chat/Admin DTOs
   available while v2 is introduced behind a feature/provider boundary.
2. Add new schema only through additive migrations. Do not delete or rewrite
   existing conversation, consent, action, provider, source or customer rows.
3. Pin catalog/persona/session state for new v2 turns; existing sessions remain
   on their stored versions until an explicit, audited migration is verified.
4. A failed model/tool/provider turn must leave the prior durable revision,
   pending requirement, consent and action state intact. Ambiguous provider
   writes remain `reconcile_required`/equivalent, never blindly retried.
5. Rollback is the prior Node provider/orchestration path plus restoration from
   the existing PostgreSQL backup and migration chain. No rollback operation
   was executed during this audit.

## Baseline blockers and follow-up

- The deterministic embedding timeout is a pre-existing local baseline defect;
  it must be isolated before relying on the full Node suite as a v2 gate.
- The Python model adapter type errors must be corrected in the appropriate v2
  issue, with typed contracts and focused tests; this baseline does not hide or
  reclassify them as passed.
- Python gateway tests require an approved local Python test environment or a
  container execution path; no Azure key or provider call is required for the
  unit tests.
- Azure GPT deployment readiness, strict catalog v2, provider sandbox/mock
  evidence and all later v2 components remain open implementation work.

## Security and compatibility review

No secrets, tokens, PII, OTPs, raw documents or provider credentials were added
to this report. Existing tenant isolation, consent, PII masking, action
idempotency, callback correlation and provider-verification controls remain
retained. This report records current evidence only and does not claim a
working v2 customer runtime.
