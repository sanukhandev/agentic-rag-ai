# V2-P5-04 — PII, credential, document and audit boundary

Status: verified code gate; production secret-rotation approval remains blocked.

## Scope

The v2 model path keeps identity, tenant, session, opportunity, consent and
provider authorization in Node. The Python gateway receives masked text and
strict typed envelopes. The v2 Node registry remains read-only; model output
cannot select an n8n endpoint, authorization header, provider credential,
payment operation or document write.

## Correction

The existing masking boundary protected reversible email, phone, name and ID
tokens, but credential-shaped values in customer text or OCR summaries were
not explicitly removed before downstream use. A shared non-reversible
credential sanitizer now removes OTP/verification codes, CVV/CVC/security
codes, card/PAN numbers, bank-account numbers and secret assignments. It runs
before reversible PII token allocation and is also applied when composing
document/CRM summaries. No credential is placed in the token vault.

Prompt-injection text remains data and is not interpreted as an instruction;
provider secrets are redacted. Existing private document storage, upload
consent, tenant-scoped tool scope, source ACL/revocation checks, HMAC service
authentication, n8n request signing and opaque provider references remain in
force.

## Production limitation

No existing n8n credential value was read or rotated. Owner-approved secret
rotation and sandbox/provider review remain an operational gate; no credential
or real customer data was used. The implementation fails closed for missing
private secrets and does not expose them to the model or public API.

remain excluded. No payment or legally binding signature was performed.
