# V2-P5-02 — Durable outbox, Redis Streams and retry safety

Date: 2026-10-30
Issue: GitHub #109
Branch: `feat/conversation-engine-v2`

## Result

Verified the existing Node ActionRequest → transactional outbox → Redis
Streams → n8n bridge path and fixed the in-memory store parity gap. The
in-memory outbox now applies the same `(stream, idempotencyKey)` uniqueness
already enforced by PostgreSQL, so tests cannot accidentally accept duplicate
durable work.

The existing event path remains authoritative for dispatch: it claims durable
execution before calling n8n, sends only server-selected registry routes,
uses bounded transient retries, preserves accepted/terminal provider states,
and moves ambiguous or unavailable writes to reconciliation/DLQ. Redis
consumer leases and inbox claims prevent duplicate provider effects after
worker replay.

## Failure handling

The first parallel full-suite attempt had one timing-sensitive existing
`channel-auth` test timeout at the default 5-second test timeout. The isolated
rerun passed (2/2), and the full suite was rerun with the bounded 15-second
test timeout and passed 280/280 executed tests. No production timeout or
retry behavior was changed for that test-only scheduling fluctuation.
