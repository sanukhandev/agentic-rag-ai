# V2-P6-01 — Stage 1 Lead provider contract

Status: verified with deterministic mock evidence; live Salesforce sandbox
completion remains blocked pending approved provider inputs.

## Implementation

`services/api/src/v2-lead-provider.ts` defines a strict v2 Lead
create-or-dedupe request/result contract and a deterministic mock adapter.
Requests bind the tenant, application session, opportunity, pinned catalog,
action identity/revision, idempotency key and opaque local payload reference.
No customer PII, provider credential, endpoint or authorization header is part
of the model-facing or provider request contract.

The request builder requires an approved/processing action, matching Lead
identity, valid contact completeness and explicit contact consent. The mock
adapter returns a clearly marked `mock_verified` result and reuses the same
result for the same tenant/idempotency key. Result validation requires exact
correlation and rejects unknown evidence, provider-type mismatches and
ambiguous notification status as `reconciliation_required`.

The existing Node action gateway, transactional outbox, n8n signing,
tenant/session authorization and callback evidence tiers remain the execution
boundary. No published v2 catalog binding or live provider credential was
enabled by this change.
