## Result

**VERIFIED for the private Python coordinator.** The new coordinator is
available at the internal `/internal/v2/conversation/turn` boundary and uses
the frozen v2 envelope. It is not a public Chat API and is not wired as a
replacement for the existing Node coordinator. Issue #99 owns the authenticated
Node trusted-tool gateway that will supply the injected tool executor.

## Implementation

- `services/model-gateway/gateway/agent.py` runs one Responses request followed
  by bounded function-call/output continuation requests.
- `tool_definitions.py` is the single strict registry for the eight approved
  read-only Node tools. Unknown or unadvertised names are denied.
- Tool arguments are parsed as JSON and validated through `ToolRequestV2`; the
  model cannot provide tenant, session, opportunity or scope identity.
- Duplicate call IDs reuse the first sanitized result and do not execute the
  gateway twice.
- Tool results are bounded, hashed in trace metadata and never returned as raw
  customer output. Provider/tool failures become typed unavailable results.
- Model request count, tool calls, tool rounds and the shared deadline are
  enforced. Exhaustion returns a typed persona-pinned fallback.
- `HttpToolGateway` only calls the private future Node tool route and has no DB,
  CRM, n8n, payment, shell or arbitrary URL capability.
- The internal route requires the existing private service key and returns the
  internal `AgentTurnResultV2`; public Chat/Admin contracts are unchanged.
