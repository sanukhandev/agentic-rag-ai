# V2-P4-01 — Natural Persona Composer

Date: 2026-10-30
Issue: GitHub #103
Branch: `feat/conversation-engine-v2`

## Result

**VERIFIED for the private Python Conversation Agent runtime.** The final
response path now derives its instructions from the session-pinned tenant
persona and validates the structured response before returning it. The change
does not hardcode Zara, replace tenant configuration, authorize actions, or
change the public Chat/Admin contracts.

The composer accepts only the configured persona version and permitted
language, keeps the answer grounded in masked context and approved tool
observations, permits one relevant question or a legitimate no-question
exception, and rejects internal identifiers, tool/protocol metadata, JSON
payloads and prompt leakage in customer-facing text. The existing typed
fallback remains the safe result for invalid output.

- Complete Python model-gateway suite: **21 passed, 0 failed, 1 warning**.
- The suite was run in an ephemeral Compose test container with the checked-out
  `services/model-gateway` mounted at `/workspace`; no image or credential

- API contracts, Node tool authorization, catalog/stage planning, response

## Scope and limitations

The Python runtime receives the actual session-pinned persona from Node. This
issue verifies persona isolation and final-output safety; it does not claim
that external Salesforce, payment or signing providers completed any action.
The ANCFZ English persona is therefore configuration-driven and must remain
published and pinned by the existing Node catalog/persona path.
