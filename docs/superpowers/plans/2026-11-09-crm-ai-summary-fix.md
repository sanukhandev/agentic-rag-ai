# CRM AI Summary Reliability and Privacy Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Admin CRM “AI summarize” action call the private model gateway reliably, preserve privacy-token state across OCR callbacks, and return a typed error instead of a generic 500 when summary data is unsafe.

**Architecture:** Node remains the authenticated Admin API and privacy/business-state authority. The private Python model gateway receives only bounded masked CRM data through a new authenticated summary operation; Node validates and formats the response before persistence. OCR callbacks persist any newly created session tokens before composing CRM or Salesforce-facing summaries, while identity-document OCR text is kept out of external CRM descriptions.

**Tech Stack:** TypeScript, Express, PostgreSQL, Zod, FastAPI/Pydantic, Azure OpenAI Responses API, Docker Compose, Vitest/Node tests.

**Spec:** `docs/requirements.md`, `docs/architecture.md`, `docs/current-state.md`, `docs/n8n-workflows.md`, and the existing privacy contract in `services/api/src/privacy.ts`.

## Global Constraints

- Node is the sole authority for admin authorization, tenant scope, privacy-token validation, summary formatting, and database writes.
- Python is inference-only and receives masked, bounded input; it never receives identity-document bytes, credentials, direct database access, or n8n URLs.
- Keep existing tenant isolation, auth, consent, token vault, and audit protections; do not weaken `assertKnownTokens` to hide the defect.
- Do not claim AI generation when the model gateway is unavailable; return a typed `CRM_SUMMARY_AI_UNAVAILABLE` response.
- Use synthetic/local data for verification; do not call production Salesforce, charge payments, or send real customer documents.
- Preserve the existing Admin API response shape: `{ lead, aiGenerated }`.

## Review Focus

- OCR introduces a new `[ID_n]` or `[PHONE_n]` token: the token must be durable before the summary is composed.
- The model gateway is unavailable or returns malformed output: the API must return a typed 503 and never persist a fabricated summary.
- The model returns an unknown privacy token or raw sensitive text: Node must reject it without a generic 500 or data leak.
- An identity-document OCR result contains names, dates of birth, MRZ data, or filenames that resemble IDs: external CRM descriptions must contain only safe document metadata.
- A replayed admin summarize request: it must update the same lead idempotently without creating a second lead or audit side effect beyond the intended summary audit.

## Completion Criteria

- The reported request path no longer returns `INTERNAL_ERROR` for valid OCR-backed leads.
- A configured local model gateway produces `aiGenerated: true` through the V2 runtime.
- OCR-created privacy tokens survive callback/session reloads and are validated before persistence.
- Identity-document OCR content is not sent to Salesforce or included in the CRM summary fed to AI.
- Model outage, malformed output, and unknown-token cases return typed errors and preserve the previous summary.
- Focused tests, full workspace checks, Docker readiness, and one redacted authenticated E2E artifact all pass.
