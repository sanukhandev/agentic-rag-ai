# Legacy conversation dependency inventory (V1 → GPT-first V2)

Snapshot: `3a4ca0b34af88f2056592b404ee0c9505aa6965b` (2026-11-02). **Static inventory, not a deletion authorization.** This branch does not change production controllers, catalog, gateway, stores, actions, providers, or migrations. Entries are classified at **function/route level** when modules mix V1 and V2.

## Runtime entry points and dependency edges

1. `services/api/src/index.ts` is the Node production entry (`services/api/package.json`: `start` → `dist/index.js`). It constructs `PostgresStore`/`MemoryStore`, cache, embedding, and `V2ConversationCoordinator` when V2 is enabled and gateway credentials exist. When `CONVERSATION_ENGINE_V2_ENABLED=false`, it can construct `pythonChatModelFromEnv()` for explicit V1 rollback (`CHAT_MODEL_PROVIDER=python-gpt`).
2. `services/api/src/app.ts` exports `createApp`; `POST /api/v1/chat/messages` chooses `runGPTFirstChatTurn()` (`v2-turn-controller.ts`) only if the V2 coordinator exists **and** `conversationEngineV2EnabledForTenant()` accepts the tenant. Otherwise the same public endpoint runs the legacy Node planner, `runAgentTools`, `resolveIntent`, V1 message composition and its state transitions. A separate older V2-in-legacy-dialogue branch is still present around lines 1868–1931. Both must be considered before code removal.
3. `services/api/src/v2-turn-controller.ts` → `v2-coordinator.ts` → authenticated `POST /internal/v2/conversation/turn` (`services/model-gateway/gateway/app.py`) → `LangGraphConversationAgent` or bounded agent → authenticated Node `POST /internal/v2/tools/execute` (`v2-tool-gateway.ts`). Python's allowed tools are read-only; Node owns persistence, consent, action gates, business state and callbacks.
4. The older Python adapter (`services/api/src/python-model/chat-model-adapter.ts`) → `POST /internal/v1/model/plan` and `/internal/v1/model/normalize` (`gateway/app.py`) → `gateway/contracts.py`. Its `draft`, `compose` and `normalizeQuery` are reachable by the rollback path. The `planV2` method also calls the V1 endpoint but is not part of the authoritative GPT-first controller.
5. Other active API entry points **remain** in `app.ts`: chat session/config/history, action confirmation/status/follow-up, supporting documents, Admin/catalog, workflow/provider callbacks, event handling and auth. `model.draft()` also supports reconciliation replies; `model.summarize()` may be used in CRM admin summaries. Do not delete the whole module.
6. Python deployment entry is FastAPI `gateway.app:app` in `services/model-gateway/Dockerfile`. `docker-compose.python-gpt.yml` injects the gateway URL, credentials, `CHAT_MODEL_PROVIDER=python-gpt` and V2 enable/tenant flags. The overlay is not a retirement signal. `services/model-gateway/gateway/mock_model.py` is referenced by the active Python gateway, including V2 mock testing.
